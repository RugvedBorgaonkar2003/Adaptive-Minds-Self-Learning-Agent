CHANGELOG: onboarding.py
================================================================================

--- BEFORE ---
- Contained a full LangGraph setup (`StateGraph(OnboardingState)`) with:
  - `interview_node`: Conversational LLM node that checked which of the 4 variables (topic, level, goal_type, sources) were missing and queried the user.
  - `extraction_node`: Silent LLM node that extracted data using complex, error-prone JSON instruction prompts and executed `json.loads(raw_content)` with regex-like sanitization.
- Contained `run_onboarding()` which ran an interactive command line loop using `input()`.
- Had an API helper `run_onboarding_api(request)` that mapped a Pydantic object but did no safety validation for missing required inputs or `NoneType` values inside `sources_list` (which caused crashes if `None` was sent).

--- AFTER ---
- Completely removed LangGraph, LangChain imports, and LLM-based interviewing/extraction nodes, eliminating latency and LLM JSON parsing hallucination bugs.
- Deleted the unused command line helper `run_onboarding()`.
- Refactored `run_onboarding_api()` to perform clean, deterministic Python validations:
  - Validates that the mandatory fields (`topic`, `level`, `goal_type`) are not empty or blank.
  - Gracefully processes `sources_list` using python checks (filters out empty or spaces-only items and safely handles `None`).
  - Correctly sets `sources_uploaded` to `False` if no valid sources are present, prompting downstream components to trigger autonomous self-scraping/research.

CHANGELOG: orchestrator.py & scraper.py
================================================================================

--- BEFORE ---
- **Blocking I/O**: Heavy synchronous parsing tasks (PDF extraction, YouTube fetching, Arxiv downloads) blocked the main FastAPI async loop.
- **Silent Failures**: Arxiv downloads failed silently if API limits were hit or the download didn't finish before the parser kicked in.
- **URL Duplicates**: The scraper often scraped the same URL multiple times (e.g. `example.com` vs `example.com/`).
- **PDF Edge Cases**: Allowed any local file not starting with `http` to trigger the PDF parser, leading to crashes on `.txt` or `.docx` files.
- **Weak Quality Gate**: The AI research agent's quality check was loose (just a true/false evaluation) and allowed SEO spam and irrelevant domains into the knowledge base.
- **Token Limits**: Evaluated knowledge sufficiency by sending the raw massive text chunks to the LLM, breaking token limits quickly.
- **Hardcoded Test Bloat**: Kept development/testing scenarios bundled inside `orchestrator.py`.

--- AFTER ---
- **Non-Blocking Architecture**: Wrapped all synchronous functions (like `self.pdf_parser.parse_pdf` and `self.arxiv_searcher.search_and_download`) inside `await asyncio.to_thread(...)`, keeping the backend fully async and responsive.
- **Robust Arxiv Handling**: Wrapped Arxiv downloading in a `try...except` block and safely verified file existence on disk before parsing.
- **URL Normalization**: Created a strict `_normalize_url` helper that standardizes URLs before duplicate checking.
- **Strict Parsing**: Enforced a strict `.pdf` file extension check before triggering local PDF parsing.
- **Multi-Layered Quality Gate**: 
  - *Layer 1 (Blacklist)*: Statically blacklisted common SEO/paywall farms (`quora.com`, `pinterest.com`, `chegg.com`).
  - *Layer 2 (Heuristics)*: Reject content under 500 characters instantly.
  - *Layer 3 (Strict Rubric)*: The LLM grades sources from 1-10 on Relevance, Depth, and Authority. A source needs a score >= 8 to pass.
- **Token Limit Fix**: Knowledge sufficiency evaluation now generates a lightweight "Markdown Heading Outline" (Table of Contents) from the gathered knowledge, preventing token limit crashes.
- **Clean Separation**: Abstracted the testing logic to an external `orchestrator_testing.py` file.

CHANGELOG: scraper.py (Query Fanout & Optimization)
================================================================================

--- BEFORE ---
- **Sequential Scraping**: The agent looped through generated queries one by one, searched DuckDuckGo, and then scraped each URL sequentially. This took several minutes because it waited for network I/O for each single step.
- **Vulnerable to Rate Limits / Anti-Bot**: Because it relied on 1 or 2 sites sequentially, if a site blocked Crawl4AI (e.g. Cloudflare captcha), the agent would fail to gather knowledge for that topic.
- **Short YouTube Videos Accepted**: If a YouTube video had a 5-second transcript ("Subscribe to my channel!"), the parser accepted it as a valid source.

--- AFTER ---
- **Query Fanout (Parallel Computation)**: 
  - Implemented `asyncio.gather` for both web searching and web scraping inside `conduct_research`.
  - The agent now fires off all search queries concurrently, pools all the unique URLs, and scrapes a massive batch of URLs (up to `MAX_SCRAPE_LIMIT`) concurrently.
  - This effectively bypasses anti-bot defenses: even if a few major sites block the scraper, the wide parallel net instantly catches data from other smaller, relevant blogs.
  - Reduced network waiting time from minutes to seconds.
- **Sequential Quality Gate**: While fetching is concurrent, passing the fetched text through the LLM `evaluate_source_quality` is done sequentially to avoid triggering LLM API rate limits.
- **YouTube Heuristic Added**: Updated `get_youtube_transcript` to measure the extracted text length. It instantly rejects and returns an empty string if the transcript is under 500 characters, mimicking the web layer heuristic.

CHANGELOG: scraper.py (DOM Sniper & Quality Gate Tuning)
================================================================================

--- BEFORE ---
- **Overly Strict Quality Gate**: The quality gate required a perfect 8/10 score. This caused it to falsely reject highly educational but structurally dense pages.
- **Blind Scraping**: `crawl4ai` blindly extracted all text on the webpage, meaning it included massive navigation sidebars, footers, and cookie banners.
- **False Negatives**: Because the LLM evaluated the first snippet of text (which was often just the "Main Menu" links), it assumed the page was irrelevant and rejected top-tier websites like TensorFlow Docs and Wikipedia.
- **YouTube Version Bug**: Used `YouTubeTranscriptApi.list_transcripts()`, which caused an `AttributeError` on older versions of the library.

--- AFTER ---
- **Relaxed Quality Gate**: Lowered the passing score from 8 to 6 and updated the prompt to allow for pages that aren't "perfect" but are "useful enough to learn from".
- **DOM Sniper (CSS Exclusions)**: 
  - Fed a strict `excluded_tags` list into `crawl4ai` (`['nav', 'aside', 'footer', 'header', 'iframe', '.cookie-banner', '.adsbygoogle', '#sidebar', '.sidebar']`).
  - The scraper now surgically deletes all boilerplate and distractive elements *before* parsing the text, guaranteeing the LLM only evaluates the pure article content.
- **YouTube API Fix**: Swapped `list_transcripts()` for the universally compatible `get_transcript()` method, permanently resolving the versioning crash.

CHANGELOG: Generation Modules & AI Tutor Architecture
================================================================================

--- BEFORE ---
- **The Truncation Bug (`curriculum_gen.py`)**: Blindly chopped Vector DB context at exactly 12,000 characters, risking slicing words or critical math formulas in half and confusing the LLM.
- **The JSON Regex Trap (`curriculum_gen.py`, `tutor.py`)**: Regex for extracting JSON (`re.search(r'\{.*\}')`) failed and crashed instantly if the LLM outputted standard markdown backticks (e.g., ` ```json `).
- **The Silent Psychologist (`tutor.py`)**: The `insight_node` swallowed its JSON crashes in silence (`except Exception: pass`), meaning the `student_profile` metrics (boredom, confusion) were permanently frozen.
- **The RAM Killer (`tutor.py`)**: The Teacher node forced the backend to load a brand new 300MB HuggingFace Math Model into RAM every single time the user sent a message, guaranteeing a fatal server crash within 10 messages.
- **Robotic Persona (`tutor.py`)**: The Tutor outputted sterile Wikipedia-style markdown (hashtags, bolding) and ignored the student's psychological profile.
- **The Infinite Context Bomb (`tutor.py`)**: The Teacher appended the entire chat history forever. A long conversation would instantly blow past the LLM token limit.

--- AFTER ---
- **Iterative Context Packing (`curriculum_gen.py`)**: Replaced blind truncation with a loop that perfectly packs whole chunks one by one, stopping safely before the 12,000 limit without ever breaking a sentence.
- **Aggressive Markdown Stripping**: Added a sanitizer (`.replace("```json", "")`) before every single Regex extraction, completely neutralizing the JSON parsing crashes across all generation modules.
- **Psychologist Logging (`tutor.py`)**: Removed the silent `pass` in `insight_node` and added explicit error logging so metrics can be actively debugged.
- **Singleton DB Cache (`tutor.py`)**: Implemented a global `_db_cache` dictionary at the top of the file. The HuggingFace embedding model is now safely loaded exactly ONCE per session and instantly reused for all subsequent messages, dropping RAM usage to almost zero.
- **Dynamic Personality Engine (`tutor.py`)**: Radically rewrote the system prompt. The Tutor now shifts its literal persona (e.g., 'warm empathetic mentor', 'fast-paced senior engineer', 'meticulous teacher') dynamically based on the student's live Confusion Matrix. Strictly banned all markdown formatting to force a natural, human-to-human conversational tone.
- **Character-Based Sliding Window (`tutor.py`)**: Added a 5-line Context Safety Filter to both the Teacher and Examiner nodes. It reads the infinite UI chat history backwards, calculates the character length, and smoothly drops the oldest messages to maintain a strict 4000-character safe zone before pinging the LLM. Zero risk of token limit blowouts.

CHANGELOG: Database Safety & Concurrency (`student_profile.py`)
================================================================================

--- BEFORE ---
- **The Double-Click Race Condition**: Used standard `open("file.json", "w")`. If two server threads triggered a save simultaneously (e.g., rapid clicking), they would overwrite each other and instantly scramble the JSON database.
- **The Permanent Death Crash**: Used standard `json.load()`. If the server restarted during a file write, the file would corrupt. The next time the user logged in, `json.load()` would trigger a fatal `JSONDecodeError`, permanently locking the student out of the application.

--- AFTER ---
- **Thread Locking (Race Condition Fix)**: Implemented a global `threading.Lock()` traffic light. Concurrent save requests now cleanly wait in line, making simultaneous overwriting impossible.
- **Atomic Writes (Corruption Fix)**: Implemented atomic writing via `os.replace`. Data is now safely written to a hidden `.tmp` file first. Only when the save is 100% complete does it instantly snap over the real file, guaranteeing the file can never be half-written or corrupted.
- **Auto-Repair Safety Net**: Wrapped `load_profile` in a `try/except` block catching `JSONDecodeError`. If a file is somehow magically corrupted, it catches the crash, logs a warning, and instantly rebuilds a clean default profile so the student never experiences a crash or lockout.

CHANGELOG: Study Generators (`flashcard_gen.py` & `notes_gen.py`)
================================================================================

--- BEFORE ---
- **The RAM Killer**: Hardcoded `VectorDBManager()` in the `__init__` method. Every generated flashcard deck or chapter note re-loaded the 300MB HuggingFace model into RAM, causing immediate server exhaustion.
- **The Blind Truncation Bug**: Blindly chopped Vector DB retrieved text at exactly 8,000 or 10,000 characters to fit the context window, frequently cutting paragraphs or complex formulas in half.
- **The JSON Regex Trap (`flashcard_gen.py`)**: Blindly searched for JSON without stripping markdown formatting, causing fatal `json.loads` crashes when the LLM added backticks.
- **Database Race Conditions & Corrupted Files**: Both modules wrote their output directly to `.json` or `.md` files using `open(filepath, "w")`. If two users requested generation for the same topic concurrently, their save operations would collide, overwrite each other, and instantly scramble the files forever.

--- AFTER ---
- **Singleton DB Cache**: Implemented a global `_db_cache` Singleton in both modules. The Vector DB is dynamically fetched instead of initialized, completely neutralizing the RAM leaks.
- **Iterative Context Packing**: Replaced blind truncation with an iterative string packer that safely measures character counts and only packs whole paragraphs, preventing chainsawed strings.
- **Aggressive Markdown Stripping**: Added `.replace("```json", "")` to `flashcard_gen.py` before Regex extraction, permanently neutralizing the LLM backtick crashes.
- **Thread Locking & Atomic Writes**: Added `_flashcard_lock` and `_notes_lock` global traffic lights to both files. All save operations now safely queue up and write to a `.tmp` file first. The files are then atomically snapped into place using `os.replace`, completely preventing any chance of corrupted data from concurrent requests.
